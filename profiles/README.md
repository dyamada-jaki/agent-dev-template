# 作るものの種類（プロファイル）

このテンプレートのプロセス（3つの席・8ステップ・ADR・作業時間・Issue レポート）は、作るものの種類によらず同じ。
種類によって変わるのは、**何で確かめるか**だけ。それを次の3か所に集めている。

| 場所 | 変えること |
|---|---|
| `CLAUDE.md` / `AGENTS.md` の「作るもの」と「開発設定」 | 確認コマンド・テスト先行・E2E・ミューテーション・開発サーバー・ポート・画面確認の幅。使わない項目は「なし」 |
| `docs/testing.md` | 確かめ方（テストの層、レビューで見ること）。1・3・5・6章はおおむね共通、2章を種類に合わせて書き換える |
| `.github/workflows/` | CI。確認コマンドと同じものを回す |

スキルはこの表から値を読み、「なし」の項目の手順を飛ばす。「テスト先行」を「しない」にすると、テストを先に書く手順の代わりに testing.md の確かめ方に従う。

## 既定: Web アプリ（`web-app/`）
- 何もしなければこの構成。CLAUDE.md の表は、この値で埋めてある
- `web-app/ci.yml` を `.github/workflows/ci.yml` にコピーして使う
- アプリの雛形（package.json など）は入っていない。`npm create vite@latest` などで作り、確認コマンドの4つ（test・typecheck・lint・build）をそろえる
- E2E（Playwright）とミューテーション（StrykerJS）は、元のプロジェクトで使っている。必要になったら専用の Issue で導入し、表と testing.md 4章を埋める

## 新しい種類を足す
1. 最初のプロジェクトで、上の3か所を書き換えて回す。例: スライドなら、確認コマンドは「スライドのビルドとリンク切れの確認」、画面確認は「各ページの表示」、テスト先行は「しない」
2. 何本か Issue を回して落ち着いたら、このフォルダに `<種類>/` を作り、表の値・testing.md・CI を置く
3. この README の一覧に足す
